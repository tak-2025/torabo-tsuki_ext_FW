# 拡張ステータスLED 仕様

拡張基盤に載る 3色LED の仕様書。**何を表示できるか**・**左右でどう使い分けるか**・**ZMK Studio からどう設定するか**をまとめる。

> 拡張基盤の各サイドには 3色LED が 1個ずつ載っている。左右は独立に用途を割り当てられる。表示できる内容は「そのサイドが知っている情報」で決まる（§2）。

---

## 1. ハードウェア仕様

| 項目 | 仕様 | 意味 |
|---|---|---|
| 色 | 赤(P1.11) / 黄緑(P1.10) / 緑(P1.02) の **3チャンネルを GPIO で ON/OFF** | **PWM なし**＝明るさ調整・中間色は不可。発色は **7種**（＋消灯）。ただし点滅と組み合わせて語彙を増やせる（§1.1） |
| 電源 | アノードが **P0.24 = 拡張パッドの電源レール**に接続 | **拡張パッドが載っているサイドでのみ点灯**する（パッドが無いとレールが上がらない） |
| 個数 | 左右の拡張基盤に**各1個** | **左右で別々の用途に割り当て可能** |
| 消費電力 | 常時点灯は電池寿命に不利 | **イベント駆動 or 低デューティ点滅**を基本とする（§4） |

左右とも拡張パッドを載せた構成では、両サイドとも点灯可能。

### 1.1 信号の表現力 — 色 × 点滅

3チャンネルでも、**色と点滅パターンの掛け合わせ**で識別できる信号数は増える。

| 次元 | 取りうる値 | 数 |
|---|---|---|
| 発色 | 消灯を除く組合せ | **7** |
| 点滅パターン | 点灯 / ゆっくり点滅 / 速い点滅（＋ダブル点滅など） | **3〜4** |
| **1個あたりの識別可能な信号** | 色 × パターン | **21〜28** |
| **左右合わせて** | 左右は独立 | さらに掛け算 |

点滅は語彙を増やすと同時にデューティを下げて電池消費も抑える（§4）。

> **表示色の実用上の注意**: 発色は組合せ上7種あるが、**すべてが人間に見分けられるとは限らない**（例: 赤+緑 と 黄緑 単体は近い色に見えうる）。プリセットは**高コントラストな4〜5色**を既定とし、7色すべては Studio 上で上級者向けに開放する。素子の色味は実基板で確認して確定する。

## 2. 左右で表示できる情報

LEDを光らせるには、そのサイドがその情報を保持している必要がある。以下がサイド別の対応。

| 情報 | 右(central) | 左(peripheral) | 備考 |
|---|---|---|---|
| **HIDインジケータ**（Caps/Num/Scroll Lock） | ○ | ○ | ZMK が split 経由で peripheral へ中継。**追加配線なし**（左は §2.2 のビルド設定が必要） |
| 自分の電池残量 | ○ | ○ | 各サイドが自分の残量を保持 |
| 相手の電池残量 | ○ | × | central のみ（battery proxy） |
| split リンク状態 | ○ | ○ | 各サイドが自分側から見た接続を保持 |
| アイドル / スリープ | ○ | ○ | 省電力状態 |
| レイヤー | ○ | △ | peripheral は自前で保持しない → central から中継（§2.1） |
| BLEプロファイル | ○ | △ | 同上 |
| 出力先（USB/BLE） | ○ | △ | 同上 |
| 修飾キー / マウスボタン | ○ | △ | 同上 |
| ポインティングの役割（スクロール/マウス層） | ○ | △ | レイヤー連動のためレイヤーと同じ扱い |

**○ = そのサイド単体で表示可能**／**△ = central から情報を中継して表示可能**（§2.1）。原理的に表示できない用途はない。

### 2.1 左（peripheral）での表示のしくみ

- **左が単体で表示できるもの**（中継なし）: 自分の電池残量、central とのリンク断、Caps/Num/Scroll Lock、アイドル/スリープ。これらは左のLEDにそのまま出せる。
- **central 由来の情報**（レイヤー・修飾キー・BLEプロファイル・出力先など）: これらは central が保持するため、central から左へ情報を送って表示する。central は「左に何を出すか」を計算して**左にだけ**送り、自分のLEDは自分で制御する。これにより**左右を完全に独立**して扱える。

### 2.2 ビルド設定

- **左で Caps/Num/Scroll Lock を表示する場合**: `CONFIG_ZMK_SPLIT_PERIPHERAL_HID_INDICATORS=y` が必要（既定は無効）。有効化すると central のインジケータ状態が peripheral まで届く。
- **左用のLED定義**: 左の overlay に LED ノード（カソード P1.11 / P1.10 / P1.02）を追加する。電源 P0.24 は拡張パッドが上げているため、左のLEDにも電源が供給される。

## 3. 表示できる用途

**分類軸 = 「いつ光るか」**。これが電池寿命を左右する。

### 分類B: 変化した瞬間だけ光る（イベント駆動）

| ID | 用途 | 表示内容 | 左で表示 | 電池 |
|---|---|---|---|---|
| **B1** | BLEプロファイル切替 | 切替時に profile 番号を色コンボで約1.5秒 | 中継 | ほぼゼロ |
| **B2** | レイヤー変更 | レイヤーが変わった瞬間に色を約1秒 | 中継 | ほぼゼロ |
| **B3** | 出力先切替（USB↔BLE） | 切替時に色を一瞬 | 中継 | ほぼゼロ |
| **B4** | ポインティングのモード変更 | スクロール層/マウス層に入った瞬間に色 | 中継 | ほぼゼロ |

### 分類C: 異常・警告のときだけ光る（低頻度・重要）

| ID | 用途 | 表示内容 | 左で表示 | 電池 |
|---|---|---|---|---|
| **C1** | 相方を見失った | split リンク（中央↔周辺）が切れた | ○ | 低デューティ点滅で小 |
| **C2** | 電池残量警告 | 自分の電池が閾値を下回った | ○（各自の電池） | 小 |

#### C1 — 左右に載せると障害箇所が特定できる

同じ「splitリンク断」でも、見るサイドで意味が変わる。

- **右(central)から見て** = 「左が消えた」
- **左(peripheral)から見て** = 「中央を見失った」

両サイドに載せると、**どちらの半分が落ちているのかが、その半分自身のLEDで分かる**。左右の表示のしくみは次のとおり。

- **右(central)**: BLE接続のロール判定で相手の消失を検出する。
- **左(peripheral)**: リンク状態の変化イベントを購読し、現在値も読める。

> **C1 の点灯方式**: 切断したまま放置すると常時点灯は電池を消費する。**低デューティ点滅（例: 2秒に50ms = 2.5%）**にすることで消費を常時点灯の約 1/40 に抑える。

> **ホスト未接続の表示は対象外**: ホストとの接続状態は central のみが保持し（peripheral はホストと BLE 接続しない）、かつ「PCに繋がっていない」ことは実使用ですぐ分かる。リンク系の表示は C1 に集約する。

### 分類A: 状態を出しっぱなしにする（電池注意）

| ID | 用途 | 表示内容 | 左で表示 | 電池 |
|---|---|---|---|---|
| **A1** | Caps Lock 表示 | Caps ON の間ずっと | ○（配線なし。§2.2） | 中（点滅化で小） |
| **A2** | 現在レイヤーを常時表示 | 常にレイヤー色 | 中継 | 大 |
| **A3** | 修飾キー押下中の表示 | Shift/Ctrl/Alt/GUI を押している間だけ点灯 | 中継 | 小（押している間だけ） |

#### A3 — 修飾キー押下の表示

修飾キーは一過性にしか押されないため、Caps Lock のような「ONのまま放置」にならず**電池コストは小さい**。

- 修飾キーの状態は HID レポート上の修飾ビットマスクから取得する。これにより `&kp LSHFT`・mod-tap・sticky key など、**HIDレポートに乗る修飾はすべて拾える**。

**色の割り当て — 修飾キーとLEDチャンネルは相性が良い**。3チャンネル（赤/黄緑/緑）に修飾キーを割り当てると、**複数同時押しは自然に色が混ざる**（チャンネルのOR）。

| 修飾キー | 例: 割当チャンネル | 同時押しの見え方 |
|---|---|---|
| Ctrl | 赤 | Ctrl+Shift → 赤+緑（混色） |
| Shift | 緑 | Ctrl+Alt → 赤+黄緑 |
| Alt | 黄緑 | 3つ同時 → 全点灯 |
| GUI | （3ch使い切るので**点滅**で区別） | GUI+Ctrl → 赤が点滅 |

修飾キーは4つ、チャンネルは3つなので **GUI だけ点滅で表現**する。どの修飾にどの色を割り当てるかは **Studio から設定可能**。

> **消灯について**: 「何も光らせない」は用途ではなく、**単に何も割り当てていない状態**（各サイドの既定＝未割当＝消灯）。

## 4. 電池の消費特性

PWMが無いため、消費は明るさではなく **「光っている時間の割合（デューティ）」**で決まる。

- **イベント駆動（分類B）** … 1日に数十回×1秒 → 実質ゼロ。制約なく利用できる。
- **低デューティ点滅（分類C）** … 2秒に50ms = 2.5% → 常時点灯の約 1/40。警告用途に実用的。
- **常時点灯（分類A）** … 最も重い。利用する場合は点滅化を既定とする。

**既定方針: 常時点灯モードは選択可能だが既定にしない。既定はイベント駆動＋低デューティ点滅。**

## 5. 設定モデル（ZMK Studio）

- **設定ストア ＋ 専用GATT ＋ Studio タブ**（`torabo-encoder` と同型。既存の trackpad/encoder の配線には影響しない）。
- **左右それぞれに用途を割当**（例: 左＝修飾キー、右＝プロファイル＋警告）。**左右は完全に独立**。
- 同時に複数を有効にする場合の**優先度**: 警告(C) > 通知(B) > 常時(A)。
- **色 × 点滅パターン**を Studio から割当（§1.1）。
- 左で central 由来の情報（B1〜B4 / A2 / A3）を表示する場合は、central から左へ情報を送る経路を用いる（§2.1）。
- 未割当のサイドは消灯（省電力の既定）。

---

## 6. 推奨設定例

迷った場合の既定構成。

- **左** = **A3 修飾キー表示**（Shift/Ctrl/Alt/GUI を押している間だけ点灯。一過性なので電池に優しい）
- **右** = **B1 プロファイル表示** ＋ **C1 切断警告（点滅）** ＋ **C2 電池警告**
- **A1 Caps Lock** は左右どちらでも配線なしで追加できる。修飾キー表示と同居させる場合は優先度で調停する。
- **B2 レイヤー表示** は必要に応じて追加する。
